# Translating Little Log

Every text the app shows is in English in the code, wrapped in `__()`, `__h()`, `__n()` or `N_()` (see `i18n.js`).

- `lang/en.json` is the English source: every text, with its id, where it is used and any note for translators. It is generated by `node scripts/i18n.js extract`, so don't edit it by hand.
- Each language has one file, `lang/<code>.json`, mapping ids to translations:

```json
{
  "c1brr9": "Toma",
  "1m0pkjg": { "one": "{n} toma", "many": "{n} tomas", "other": "{n} tomas" }
}
```

A text with plural forms (it has `one` and `other` in `en.json`) takes an object with the forms the language uses. These are the CLDR plural categories, which you can list with `node -e "console.log(new Intl.PluralRules('pl').resolvedOptions().pluralCategories)"`. For example:

- Japanese uses only `other`.
- Polish uses `one`, `few`, `many` and `other`.
- Arabic uses all six: `zero`, `one`, `two`, `few`, `many` and `other`.

`{n}` is the number.

The id is a hash of the English text. When the English changes, its old translation is no longer used: the app shows English there until the new text is translated. `check` then reports the new text as missing and the old translation as stale.

## Rules

1. **Keep every `{placeholder}`** exactly as it is. The app fills them in with names, numbers, times and other texts, and the notes say what each one is. You may move them anywhere in the sentence.
2. **Keep the `**bold**` markers.** Use the same number of them as the English, around the words that match.
3. **No HTML.** The app escapes everything.
4. **Short labels stay short.** This covers:
   - the bottom tabs (Day, Month, Stats, Guide, Family, More), which are a single short word;
   - buttons;
   - the AM/PM and 24 h/12 h switches.
5. **Keep names as they are:** Little Log, Google Drive, Dropbox, OneDrive, iPhone, Android, formula brands, file types (JSON, CSV), units (ml) and the example address `you@example.com`.
6. **The Guide is medical advice.** Translate it accurately and plainly.
   - Keep every number, dose, temperature, age, time and unit exactly as written.
   - Where a medicine has a different usual name in your language, use that name. You can keep the English in brackets.
   - `{sos}` is the emergency number where the family is, or "your local emergency number".
7. **Address the reader as a warm, friendly app for parents would** in your language, and stay consistent throughout.
   - In German, for example, use `du`.
   - In Japanese, use です/ます.
   - The Portuguese is Brazilian Portuguese (`você`, celular, bebê, registro); the app calls it Português (Brasil).
8. **Read the notes.** The `note` next to a text in `en.json` explains short or ambiguous texts, for example:
   - whether "Left" means the breast side;
   - what fills a `{what}` placeholder.
   
   When there is no note, `where` names the file and line where the text is used.
9. **Values in the log stay in English.** Symptoms, poo colours and the other answers in the log are saved in English and translated only when they are shown. So each of them is a separate text to translate, like any other.

## Checking

```sh
node scripts/i18n.js check es      # what is missing or wrong in Spanish
node scripts/i18n.js status        # how complete each language is
node tests/languages.test.js       # the app in every language: plurals, dates, right to left, fallback, and the report button
```

`check` reports these problems:

- missing and stale ids;
- placeholders that differ from the English;
- `**bold**` markers that differ from the English;
- HTML;
- plural forms the language doesn't use, or is missing.

## Adding a language

1. Add `[code, name in the language itself]` to `LANGS` in `i18n.js`. Add `, 1` as a third item if the language is written right to left. The code is a BCP 47 code: `es`, `fil`, `zh-Hans`.
2. Write `lang/<code>.json`. Start from the ids in `lang/en.json`.
3. Run `node scripts/i18n.js check <code>` until it reports no problems.
4. Run `npm run build`. The build turns each `lang/<code>.json` into `www/lang/<code>.js`, which the app loads when that language is chosen.

## When the English changes

Run `node scripts/i18n.js extract` after changing or adding text in the code. The languages test fails while `lang/en.json` is out of date. Then run `node scripts/i18n.js status` to see what each language now needs.

## Reports from people using the app

**More → Language → Report a language issue** sends what the person wrote and the language and screen they named, by email. It sends nothing about who they are. The email goes to an address that is set only on the server: see "Language reports" in the main README.
